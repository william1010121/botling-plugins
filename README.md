# botling-plugins

Plugins for [Botling](https://github.com/william1010121/Botling), the desktop app that runs a team of
Claude Code and Codex bots. One folder per plugin; `index.json` at the root lists them all (name,
version, license, permissions, minimum app version, a hash of each folder) and is what the app's
Plugins page will read.

## Plugins

| Plugin | What it does | License |
|---|---|---|
| [`ccb-laas`](ccb-laas) | LaTeX quick typing in the composer: `;a` becomes `\alpha` (a port of web-laas / Emacs laas, plus cdlatex keys); `$…$` turns into rendered formulas when you leave the box (bundles MathJax, Apache-2.0). | GPL-3.0-or-later |
| [`ccb-session-usage`](ccb-session-usage) | A usage bar above the composer for Claude, Codex and Antigravity sessions: context %, tokens and an API-equivalent cost estimate, subagents included; click for a detailed card. | MIT |
| [`ccb-web-extractors`](ccb-web-extractors) | Scripts that read the conversation on a web AI's page (Gemini, ChatGPT, Claude, Grok) into text for the main bot. | MIT |
| [`ccb-teams`](ccb-teams) | Two temporary teams the main bot can start: a research team (one-page report with sources) and a prototype team (a small working build). | MIT |
| [`botling-components-basic`](botling-components-basic) | 17 generic cards for chats and the Board: commit log, git diff, GitHub CI, changelog, release progress, CPU / memory / disk usage, contribution board, engine skills, architecture diagram, multi-select, weather, web preview, script picture, component kit, versions summary. | MIT |

## License

There is no single license for this repository: each plugin folder carries its own `LICENSE`
file, and the `license` field of its `package.json` names the same license (see the table above).
`ccb-laas` also bundles MathJax and mhchemParser (Apache-2.0); see its `THIRD-PARTY-NOTICES.md`.

## Install a plugin

Botling never installs anything by itself: every install goes through an install card that shows
the source, license, permissions and any MCP tools, and nothing happens until you press Install.

- **Now:** clone this repo, then ask the main bot to install the plugin from its folder, for example
  "install the plugin in ~/Downloads/botling-plugins/ccb-laas". The bot answers with the install card.
- **Soon:** the app's Plugins page gets an Explore tab that reads `index.json` and installs a plugin
  from its folder here, pinned to a reviewed commit.

A plugin needs the Botling version in its `engines.ccb` (all of these: 2.0 or later).

### Cards that run a command

Some cards in `botling-components-basic` fill themselves from a script in its `scripts/` folder. Their
`Command:` lines name the script as `"$BOTLING_DATA_DIR/plugins/botling-components-basic/scripts/…"`;
Botling sets `BOTLING_DATA_DIR` to its data folder, so the line works wherever the app keeps it. A
card runs its command only after you press "Allow and run" on it.

## Layout

```
<plugin>/package.json   the manifest (name, version, license, engines.ccb, ccb.permissions, parts)
<plugin>/dist/          the web and program parts, bundled (kept in the repo: the app loads them as they are)
<plugin>/claude/        a Claude Code plugin (skills, agents, .mcp.json)
<plugin>/components/    cards: one folder each with template.html and about.md
index.json              generated by tools/build-index.mjs; do not edit by hand
tools/                  export, index and privacy-scan scripts (see below)
```

## Checks

Every push runs `.github/workflows/check.yml`:

- `node tools/scan.mjs`: a privacy scan of every file (IP and e-mail addresses, home folder paths, SSH
  targets, keys and tokens, high-entropy strings, URLs to hosts not in `tools/scan-hosts.txt`). Reviewed
  false positives are listed by id in `tools/scan-allowlist.json`. It prints where a hit is, never the
  value. A list of private words can be given in the `SCAN_PRIVATE_TERMS` repository secret.
- `node tools/build-index.mjs --check`: fails if `index.json` does not match the folders.

## Contributing

Not open for outside plugins yet. When it is, a pull request adds or changes one plugin folder,
bumps its version, passes Botling's plugin check (`Botling --check-plugin <folder>`) and the two
checks above, and regenerates `index.json`.

Maintainers: plugins are developed in a private plugin library and copied here with
`node tools/export.mjs --from <library>`, which copies only the folders and cards named in
`tools/export.config.json`, applies the scrubs, regenerates `index.json` and runs the scan.
