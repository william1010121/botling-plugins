Multi-select question: a group of checkbox options where the user can tick one or more, plus a final "Other" field for typing their own answer. The answer is sent only when the user presses "Submit". The bot does not draw it directly: reply with <show name="multi-select">JSON</show> and the app uses this component.
Data: {"question":"Which features should this release include?","options":[{"title":"Login","detail":"Password and Apple sign-in"},{"title":"Notifications","detail":"Push and email reminders"},{"title":"Export","detail":null}],"chosen":null,"extra":null}
question is the prompt; options lists only the items the user can tick (title is the option text, detail is a short one-line description, or null if none). Do not add an "Other" option: the component automatically appends a final "Other" input.
chosen is an array of the option titles the user ticked (matching the title values in options), and extra is the text the user typed into "Other". Both are null until answered.
The user must tick at least one option or type in "Other" before "Submit" is enabled. After submitting, the bot receives a single text string: the ticked titles joined with ", ", for example "Login, Notifications"; if there is also "Other" text, it is appended as "; Other: ...", for example "Login, Notifications; Other: Support Google sign-in"; if only "Other" was filled in, the string is "Other: ...".
Once answered, the whole question is locked: ticked items show a check mark and are highlighted, unticked ones are dimmed, the "Other" text stays in its field, and all checkboxes, the input and the button are disabled and cannot be changed. Questions already answered in old conversations (chosen or extra is not null) open directly in this answered state.
On submit the component uses ccb.save to store the selection and the "Other" text in the card (data.submitted = {"chosen":[title...],"extra":"text or null"}). When the card is redrawn (switching chats and coming back, or reloading) and submitted is present, it restores the answered locked state, taking priority over chosen/extra. So it can only be submitted once, and the bot never needs to write submitted itself.
Layout: one responsive card that fits any size. On a Board tile it fills the tile and scrolls, with "Submit" kept at the bottom edge so it stays reachable; in a short or narrow tile a one-line status (how many are ticked) replaces the hint. Long option text wraps (a detail wraps to at most two lines). Ticking a box never sends anything; only "Submit" (or Enter in the "Other" field) does. An answered card that has only "Other" text (chosen null) opens in the same locked state.
